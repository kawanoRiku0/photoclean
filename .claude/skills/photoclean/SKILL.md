# photoclean

リポジトリ直下の `photoclean.py` を使う。仕様と判定ルールは `README.md` を参照。

## 原則

- **画像を Read しない**。判定はスクリプトに任せ、Claude は数値（`cache.db`・`plan.csv`）だけを見る。画像を見て判断するのはユーザーで、`review.html` を使う。
- 写真を削除しない。`apply` は `_trash/` への移動で、`_trash/` を消すのはユーザーが確認してから。消すときも `rm` ではなく Finder 経由でゴミ箱に入れる（`osascript -e 'tell application "Finder" to delete POSIX file "<path>"'`）。
- 対象フォルダに他の画像が混ざっていないか先に確認する。`scan` は指定フォルダ以下をすべて見る。

## 手順

1. **件数の確認**：拡張子ごとの件数とフォルダの分布を `find` で数えてユーザーに伝える。
2. **サンプルで試す**：EXIF の撮影日時順に並べ、連続する 200 枚ほどをスクラッチ領域にコピーする。重複は時系列で近いものにしか起きないので、ランダムではなく連続で取る。
3. `uv run photoclean.py scan <dir>` → `uv run photoclean.py plan <dir>`。
4. **閾値付近の値を確認**：README の sqlite クエリで、シャープネスの低い順・junk の高い順・カメラ機種なしの写真を出す。境界にあるファイル名をユーザーに伝え、見てもらう。
5. `open <dir>/.photoclean/review.html` で開く。赤＝移動、緑＝残す、重複はグループ内で残す 1 枚を選べることを伝える。
6. サンプルで問題なければ本番フォルダで `scan` と `plan` を実行する。重複グループのサイズ分布を出し、大きいグループ（連鎖でつながりすぎている可能性）を見てもらう。
7. ユーザーが保存した `plan.csv`（ブラウザの保存先。`~/Downloads` とは限らない）を探す。行数と、全ファイルが存在することを確かめてから `uv run photoclean.py apply <dir> <plan.csv>`。
8. 移動した枚数を理由別に報告し、`_trash/` を開く。消すかどうかはユーザーに任せる。

## 注意

- サンプルで作った `plan.csv` はファイル名が本番と同じなので、本番に使っても動いてしまう。本番の前に古いものは消してもらう。
- CLIP の `p_blurry` 単体はシャープな写真でも高く出ることがある。ブレはシャープネスを主に見る。
